Что уже готово (делать НЕ нужно): код, тесты, прокси и пересев пакетов на эмбеддинги bge-m3 — всё закоммичено и запушено. Осталось только выложить сайт и положить ключи. Всё ниже делается из папки проекта C:\project_claude\pws-rag-edu в PowerShell.
Обновлено (миграция на bge-m3): эмбеддинги теперь идут через Cloudflare Workers AI, не OpenAI — нужен отдельный секрет-набор (CF_ACCOUNT_ID + CF_API_TOKEN) в дополнение к OPENAI_API_KEY (тот остаётся только для чата). См. шаг 4 и docs/DEPLOY_CLOUDFLARE.md за подробностями.

TL;DR (для тех, кто спешит)

npx wrangler login
npm run build
npm run cf:deploy
npx wrangler pages secret put OPENAI_API_KEY
npx wrangler pages secret put CF_ACCOUNT_ID
npx wrangler pages secret put CF_API_TOKEN
npm run build
npm run cf:deploy

Между 3-м и 4-м шагом запомни имя проекта, которое выберешь (например pws-rag-edu) и адрес сайта вида https://pws-rag-edu.pages.dev. Подробности и проверки — ниже.

Что понадобится

  • Аккаунт Cloudflare (бесплатный) — на нём будет жить сайт.
  • Ключ OpenAI (sk-...) — только для чата (грейдинг).
  • Cloudflare account id и API-токен со скоупом Workers AI: Read — для эмбеддингов (bge-m3). Account id виден в дашборде Cloudflare справа на любой странице сайта; токен создаётся в My Profile → API Tokens → Create Token.
  • Терминал в папке проекта (PowerShell, как сейчас). Node и зависимости уже стоят.

1 Войти в Cloudflare

npx wrangler login

Откроется браузер → нажми Allow / Разрешить. В терминале появится «Successfully logged in». Если браузер не открылся — скопируй ссылку из терминала вручную.

Альтернатива без браузера: создать в дашборде Cloudflare API-токен (шаблон «Edit Cloudflare Workers» или права Pages: Edit) и задать его: $env:CLOUDFLARE_API_TOKEN = "токен" — тогда wrangler login не нужен.

2 Собрать приложение

npm run build

Должно закончиться «✓ built …» и создать папку dist/. Предупреждение про «chunks larger than 500 kB» — это норма, игнорируем.

3 Первый деплой (создаёт проект)

npm run cf:deploy

При первом запуске спросит:
• Create a new project? → Да.
• Project name → введи pws-rag-edu (запомни это имя).
• Production branch → можно оставить по умолчанию.
В конце выведет адрес: https://pws-rag-edu.pages.dev — это и есть сайт.

На этом шаге сайт уже открывается, НО оценка по барему пока не работает — ключа ещё нет. Это нормально, чиним в шаге 4.

4 Положить ключи секретами

npx wrangler pages secret put OPENAI_API_KEY --project-name pws-rag-edu
npx wrangler pages secret put CF_ACCOUNT_ID --project-name pws-rag-edu
npx wrangler pages secret put CF_API_TOKEN --project-name pws-rag-edu

Каждая команда попросит вставить значение — ключ OpenAI (sk-...), затем account id, затем API-токен (скоуп Workers AI) — жми Enter после каждого. Должно ответить «Successfully created secret …» трижды.

Важно: ключи вводятся только здесь (они уходят в секреты проекта Cloudflare, в код/гит не попадают). Не вставляй их в файлы и не коммить их. В браузере ученика ключей тоже нет — запросы идут через наш прокси.

5 Пере-деплой, чтобы прокси увидел ключ

npm run build
npm run cf:deploy

Секрет подхватывается функцией только после нового деплоя. После этого грейдинг через OpenAI заработает.

Проверка (1 минута)

✓ Открой сайт и сдай одно задание

  1. Открой https://pws-rag-edu.pages.dev.
  2. Пройди до пробного экзамена, ответь на одно открытое задание, отправь.
  3. Должна прийти оценка по барему с баллами по критериям (а не «самооценка»), и в панели источников видны фрагменты материалов.

Если оценка «самооценка» / поиск «недоступен»: значит прокси не достучался до OpenAI. Проверь: (а) секрет выставлен на проект pws-rag-edu; (б) ты сделал пере-деплой (шаг 5); (в) посмотри логи в реальном времени:

npx wrangler pages deployment tail --project-name pws-rag-edu

…и снова сдай задание — в логах будет видно обращение к /api/v1/chat/completions и ответ/ошибку OpenAI (например, неверный ключ или нет доступа к модели).

Если что-то пошло не так

  • «wrangler: command not found» → запускай через npx wrangler … (как в командах выше).
  • На под-страницах (refresh) — 404 → должно быть исправлено файлом public/_redirects (уже в репозитории). Если правил вручную — пересобери (npm run build) и задеплой заново.
  • Грейдинг отвечает 401/403 в логах → ключ OPENAI_API_KEY неверный или у него нет доступа к gpt-5.4-mini. Перевыставь секрет (шаг 4) и пере-деплой.
  • Эмбеддинги/поиск отвечают 401/403 или 500 «CF_ACCOUNT_ID/CF_API_TOKEN not set» → проверь, что CF_ACCOUNT_ID и CF_API_TOKEN оба выставлены, а токен даёт доступ к Workers AI. Перевыставь секреты (шаг 4) и пере-деплой.
  • Хочешь сменить модель/лимиты → они заданы в src/server/openaiProxy.ts (allowlist gpt-5.4-mini/gpt-5.4-nano, лимит вывода 512 токенов). После правки — npm run build + npm run cf:deploy.
Деньги: Cloudflare — бесплатно (статика безлимит, функции 100 000 запросов/день). Платишь только за использование OpenAI по своему ключу. Для контролируемого пилота прокси уже ограничивает модели и длину ответа.
Если ссылку будут открывать много людей (публичный класс): включи в дашборде Cloudflare Rate Limiting и/или Turnstile, а у OpenAI поставь лимит трат — чтобы ключ не «сожгли». Для closed-пилота с вашими ребятами это не обязательно.
