2. Локальный запуск

Требования

  • Node.js 20.19+ или 22.12+ (Vite 8) и npm.
  • Опционально Ollama с моделью bge-m3 — для реального мультиязычного семантического поиска. Без него приложение тоже работает (на офлайн-заглушке эмбеддингов).

Быстрый старт

npm install
npm run dev        # http://localhost:5173

Предметные пакеты (public/packs/*.pack.json) уже в репозитории, поэтому приложение запускается сразу. Производственная сборка:

npm run build      # tsc -b + vite build → dist/
npm run preview    # локальный предпросмотр собранного PWA

Реальные эмбеддинги

Пакеты в репозитории уже собраны на реальных bge-m3-векторах — все 7 через Cloudflare Workers AI (тот же бэкенд, что и на проде, см. раздел 8). Пересобрать самостоятельно через локальную Ollama (быстрее для итерации, но нужна отдельная сверка косинуса перед тем как полагаться на такой пакет в проде — npm run verify:embeddings, раздел 4):

ollama pull bge-m3
npm run seed                 # пересобрать все пакеты на реальных 1024-векторах
npm run seed -- english      # пересобрать только один предмет
Как это работает. Каждый пакет хранит, какой моделью он собран (embeddingModel) и какой размерности (embeddingDim) — размерность больше не глобальная константа. При поиске запрос эмбеддится той же моделью, иначе векторные пространства не совпадут (одинаковая размерность не гарантирует совпадение — разные модели с одним и тем же числом измерений всё равно несравнимы). Если пакет собран на модели, которая недоступна — поиск не падает: показывается понятное сообщение (мягкая деградация), и приложение автоматически восстанавливается, когда сервис снова доступен. Перед тем как доверять одному бэкенду пакет, собранный другим (например: пакет с OVMS, а рантайм — Ollama), стоит прогнать npm run verify:embeddings — сверяет косинус на фиксированном ru/ro/en наборе запросов.
OpenVINO (оптимизированный локальный инференс на Intel) — альтернатива облаку. Поддержан через OpenVINO Model Server (OVMS) с OpenAI-совместимым API: чат — пресет openvino (http://localhost:8000/v3) переиспользует общий адаптер без отдельного кода; эмбеддинги — OpenAICompatibleEmbeddingProvider против OVMS /v3/embeddings (модель — bge-m3, 1024-dim, пакеты пересобрать ею). Тот же OpenAI-совместимый хук работает и в проде — но там это Cloudflare-прокси: эмбеддинги идут в Workers AI (@cf/baai/bge-m3, тоже 1024-dim — то же пространство, что и локально), чат — в OpenAI (gpt-5.4-mini); OVMS остаётся вариантом для полностью локального/Intel-развёртывания без облака. Подробнее — docs/LLM_PROVIDERS.md.

3. Деплой на Cloudflare (реализовано)

Приложение — статический SPA + PWA на Cloudflare Pages. Динамика (LLM-грейдинг и облачные эмбеддинги) идёт через Pages Function-прокси на том же домене (/api/*), так что ключ OpenAI остаётся на сервере. Полный рунбук — docs/DEPLOY_CLOUDFLARE.md; короткая шпаргалка по шагам — docs/DEPLOY_STEPS.html.

Уже развёрнуто: проект Pages pws-rag-edu → https://pws-rag-edu.pages.dev. Деплой: npm run cf:deploy (он же подхватывает functions/); секрет OPENAI_API_KEY задан через wrangler pages secret put. Шаги ниже нужны для повторного деплоя/настройки с нуля.

Шаг 1. Хостинг на Cloudflare Pages

  1. Авторизация: npx wrangler login (или токен CLOUDFLARE_API_TOKEN с правом Pages:Edit).
  2. Сборка и деплой: npm run build, затем npm run cf:deploy (= wrangler pages deploy dist). При первом запуске создаётся проект Pages.
  3. SPA-маршрутизация: файл public/_redirects (/* /index.html 200) уже в репозитории — прямые ссылки/refresh на /exam, /practice и т.д. отдают приложение. Pages Functions (/api/*) матчатся раньше этого правила, поэтому прокси не задевается.
  4. Прокси: functions/api/[[path]].ts → src/server/openaiProxy.ts обслуживает /api/v1/* (деплоится автоматически вместе с Pages).

Шаг 2. Эмбеддинги в облаке

Решение (обновлено после миграции на bge-m3): запрос и пакет должны жить в одном векторном пространстве, а у учеников нет локальной Ollama. Эмбеддинги идут всегда через прокси, но не в OpenAI, а в Cloudflare Workers AI (@cf/baai/bge-m3, 1024-dim) — через её же OpenAI-совместимый эндпоинт, так что OpenAICompatibleEmbeddingProvider на фронтенде не меняется. Причина смены бэкенда: одна и та же модель должна стоять и локально (демо на Intel), и в проде — OpenAI не хостит bge-m3, Workers AI хостит. Перед деплоем пакеты нужно пересеять этой же моделью (шаги с ключом — в разделе 4). Дефолт уже выставлен: DEFAULT_EMBEDDING_CONFIG = { backend:'openai-compatible', baseUrl:'/api/v1' }.

Полностью офлайн-вариант тоже остаётся возможным (EMBED_MODE=deterministic npm run seed → лексический поиск без бэкенда), но для реальной семантики выбран Workers AI (эмбеддинги) + OpenAI (чат).

Шаг 3. Чек-лист деплоя

  • Пересеять пакеты на bge-m3 @ 1024 (раздел 4, шаг A) и закоммитить.
  • npx wrangler login → npm run build → npm run cf:deploy.
  • Положить ключи секретами: wrangler pages secret put OPENAI_API_KEY (чат), CF_ACCOUNT_ID и CF_API_TOKEN (эмбеддинги, скоуп Workers AI), затем пере-деплой.
  • Проверить: на странице открыть пробный экзамен, сдать одно открытое задание → оценка по барему (не фоллбэк-самооценка), панель источников показывает чанки.
  • Проверить установку PWA и офлайн-режим на мобильном.

4. Облачный LLM + ключ OpenAI через прокси (реализовано)

Правило безопасности: рабочий ключ никогда не попадает во фронтенд или репозиторий. Ключ хранится как секрет проекта Pages, а фронтенд обращается к нашему же эндпоинту /api/v1, который подставляет ключ на сервере.

Что уже реализовано: пресет провайдера worker (по умолчанию) — kind:'openai', apiKeyMode:'proxy', baseUrl:'/api/v1', модель gpt-5.4-mini. И грейдинг, и эмбеддинги ходят на /api/v1/*, который обслуживает Pages Function functions/api/[[path]].ts → src/server/openaiProxy.ts. В браузере ключа нет (адаптер не шлёт Authorization в режиме proxy).

Пошаговые действия по ключам

Шаг A. Пересев пакетов на bge-m3 через Workers AI (один раз, нужен токен Cloudflare со скоупом Workers AI; PowerShell):

$env:EMBED_MODE = "openai-compatible"
$env:EMBED_BASE_URL = "https://api.cloudflare.com/client/v4/accounts/<CF_ACCOUNT_ID>/ai/v1"
$env:EMBED_MODEL = "@cf/baai/bge-m3"
$env:EMBED_API_KEY = "<CF_API_TOKEN>"
npm run seed
Remove-Item Env:EMBED_API_KEY          # гигиена: убрать ключ из окружения
git add public/packs/*.pack.json
git commit -m "data: re-seed packs with bge-m3@1024 (multilingual)"
Лимит Cloudflare Pages: 25 МБ на файл. При корпусе в несколько тысяч чанков на предмет пакет может упереться в этот лимит — уже случалось (раздел 1, статус-блок 24.08.2026). seed-packs.ts теперь сам округляет эмбеддинги до 5 знаков перед записью (~100x точнее, чем нужно для косинуса, но вдвое-втрое компактнее в JSON) — отдельных действий не требуется, но если пакет всё равно вырос под 25 МБ, снижайте --max-chunks в scripts/ingest-pdf.ts, а не точность эмбеддинга.

Шаг B. Положить ключи секретами проекта Pages (в репозиторий не коммитятся):

npx wrangler pages secret put OPENAI_API_KEY   # чат (OpenAI)
npx wrangler pages secret put CF_ACCOUNT_ID    # эмбеддинги (Workers AI)
npx wrangler pages secret put CF_API_TOKEN     # эмбеддинги (Workers AI, скоуп Read)
# затем пере-деплой, чтобы Function увидела секреты:
npm run build && npm run cf:deploy

Для локальной разработки/сева через прокси — файл .dev.vars (в .gitignore) со строками OPENAI_API_KEY=sk-..., CF_ACCOUNT_ID=..., CF_API_TOKEN=... и npm run cf:dev (поднимет сайт + Functions на http://localhost:8788).

Что прокси уже защищает

  • Эмбеддинги: жёстко форсит модель @cf/baai/bge-m3 и шлёт запрос в Workers AI своим ключом (CF_API_TOKEN) — вызвать произвольную/дорогую модель через ключ нельзя; клиентский dimensions отбрасывается (bge-m3 его не поддерживает).
  • Чат: allowlist моделей {gpt-5.4-mini, gpt-5.4-nano} (по умолчанию mini), жёсткий потолок вывода 512 токенов, n:1, удаление stream. Семейство GPT-5.x использует max_completion_tokens (а не max_tokens) — прокси приводит к нему автоматически.
  • Доступ: проверка Origin (запросы с чужого источника отклоняются); каждая ветка проверяет только свой секрет (OPENAI_API_KEY для чата, CF_ACCOUNT_ID/CF_API_TOKEN для эмбеддингов), заголовки к апстриму формируются заново (без утечки клиентских/ответных заголовков).
Локальная Ollama (опционально). Если на машине, где открыт сайт, доступна локальная Ollama, в Настройках появляется предложение использовать её для оценки (грейдинга) вместо облака. Эмбеддинги при этом остаются на прокси (одно векторное пространство). На захостенном HTTPS-сайте проба не проходит (mixed-content) — там остаётся облако.
Если ключ под высокой нагрузкой (много учеников/публичная ссылка): дополнительно включить Cloudflare Rate Limiting по IP и/или Turnstile (капчу), а у провайдера выставить лимит трат (spend cap). Для контролируемого пилота достаточно текущих ограничений выше.
Итог: ученик получает рабочий ИИ «из коробки» без ввода ключа, а ключ остаётся на сервере под лимитами. Для приватности по-прежнему доступны полностью локальные режимы (Ollama / LM Studio / mock).

9. Оценка сложности

Добавить новый предмет — легко

Предмет — это данные + конфиг, без изменений ядра. Шаги:

  1. Создать src/data/subjects/<id>.ts (дерево тем, типы упражнений, рубрика).
  2. Создать src/data/chunks/<id>.chunks.ts с авторскими чанками и зарегистрировать в chunks/index.ts.
  3. Добавить предмет в src/data/subjectRegistry.ts; (опц.) правила промпта в llm/promptTemplates/subjects.ts.
  4. npm run seed — собрать пакет; выставить enabled: true.
Технически — очень низкая сложность (мы добавили English, Biology, History вручную и Chemistry/Math/Russian через автоматический пайплайн PDF→чанки — без правок ядра retrieval/LLM/learning/storage). Основные затраты — контент: для авторских предметов — качественные проверяемые чанки, для автопайплайна — реальные источники (см. corpus/manifest.json) плюс очистка артефактов PDF, и в обоих случаях — учительские golden-вопросы.

11. Экономика проекта: может ли это окупаться

Честная оценка, а не питч — с реальными цифрами и явными допущениями там, где точных данных нет.

Размер рынка (Молдова)
Bacalaureat 2026: ≈18 500–19 000 абитуриентов по всей стране (moldpres.md). Русский язык обучения — 18,7% из 334,6 тыс. школьников, 250 школ (esp.md / ru.wikipedia.org). Отсюда оценка: русскоязычных выпускников BAC ≈ 3,5 тыс./год; девятиклассников (Evaluarea Națională) — того же порядка. Итого целевая аудитория «здесь и сейчас» — единицы тысяч человек в год, не миллионы.
Платёжеспособность
Средняя зарплата в Молдове — 16–17,4 тыс. леев/мес, ≈$900 (statistica.gov.md, I кв. 2026). Регулярная платная подписка для школьника — реалистично только при символической цене или через семью/школу, не «премиум SaaS».
Себестоимость
Local-first: профиль, прогресс, ответы — в браузере ученика, без серверной БД на пользователя. Переменные расходы — только облачные LLM-вызовы на оценку (сейчас лимитированы прокси: allowlist моделей, потолок токенов). Локальный OpenVINO (раздел 3) убирает и эту статью для школы, готовой держать один сервер на класс/кабинет информатики.
Реалистичная модель
Не B2C-подписка на нишевый языковой сегмент, а школа/район/грант: Министерство просвещения, образовательный фонд, донор поддержки русскоязычных школ. Дёшево обслуживать (см. себестоимость), понятная социальная миссия — сильная сторона именно для грантового/институционального финансирования, слабая — для венчурного масштабирования.
Вывод. При нынешнем охвате (Молдова, этот языковой сегмент) это не венчурный бизнес — рынок физически мал. Но при низкой себестоимости и реальном измеренном эффекте (Rescue Mode: 2 из 6 закрыли задолженности) это вполне может быть самоокупаемым проектом на школьном/грантовом финансировании — и это доказанная, не гипотетическая польза, что для такого финансирования важнее размера рынка. Путь к росту за пределы «маленького, но полезного» — не больше пользователей в Молдове, а перенос архитектуры на любой похожий сценарий: экзамен на языке большинства, ученик думает на языке меньшинства (в мире таких пар «язык меньшинства ↔ язык экзамена» много) — тогда рынок считается уже не по одной стране.
