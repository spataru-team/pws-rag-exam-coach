# Пробный экзамен с оценкой по барему — дизайн

**Дата:** 2026-06-10
**Предмет:** Limba română (`romanian`), Evaluarea Națională, 9 класс, школы с русским языком обучения
**Контекст:** экзамен 15.06.2026 (через 5 дней). Пилот на реальных учащихся в режиме «оба»: боевое использование 10–14 июня + параллельный сбор данных/фидбека для следующего цикла.
**Стратегия:** ① барем-оценка на одном прошлогоднем тесте + лёгкий захват фидбека через экспорт.

## Цель

Дать ученику пройти реалистичный пробник по аутентичному прошлогоднему тесту и получить
оценку по реальному барему (баллы по критериям + итог + точечные советы), с RAG-обоснованием.
Параллельно — собрать данные попыток и мини-фидбек для выводов к следующему потоку.

## Принцип «сначала детерминированно»

Главный архитектурный приём, снижающий риск за 5 дней: закрытые задания (mcq/short)
оцениваются локально, без LLM, и работают всегда. От LLM зависят только открытые
(written) задания, и для них есть фоллбэк на самооценку. Пробник остаётся рабочим
продуктом, даже если провайдер LLM не готов или недоступен.

## Конкретный тест пилота: pr26 «Fapte, nu vorbe»

Источник: ANCE (Молдова), «Limba și literatura română, alolingvi», pretestare, ciclul
gimnazial, 26.02.2026. 120 минут, **итог 50 баллов**. Текст для чтения «Fapte, nu vorbe»
(притча о трёх матерях; мораль «не слова, а дела»). 11 заданий:

| № | Тип | Балл | Суть | Под-барем |
|---|-----|------|------|-----------|
| 1 | open | 0–3 | дополнить 3 фразы по тексту | 1б за фразу |
| 2 | short | 0–4 | 2 синонима + 2 антонима в нач. форме | 1б за слово; есть списки принятых |
| 3 | open | 0–2 | 2 развёрнутых предложения (a juca / a se juca) | 1б за «развёрнутое» (подл.+сказ.+ещё член) |
| 4 | open | 0–4 | 4 прямых вопроса к персонажам (формы voi/vostru…) | 1б за уместный вопрос |
| 5 | open | 0–3 | моральный портрет Victoria, 3 аргум. предложения | 1б за логич./аргум. предложение |
| 6 | open | 0–2 | 2 вывода по тексту | 1б за вывод |
| 7 | short | 0–5 | перевести предложение в ед. число | 1б за корректную модификацию; эталон дан |
| 8 | open | 0–6 | продолжить диалог 6 репликами | 2б лексика + 4б за 6 реплик (3б за 5) |
| 9 | open | 0–5 | поздравление (felicitare) | 1б обращение+концовка, 1б повод, 2б особое пожелание, 1б оформление |
| 10 | open | 0–9 | эссе 8 предложений «Patria…» | репер 3б + связность 2б + объём 4б |
| 11 | correctness | 0–7 | корректность во всей работе | по числу ошибок: 0–3→7б … 24–27→1б |

Барем даёт и эталон («Răspuns corect/posibil»), и правило начисления («Specificări») —
оба заводим в `ExamItem` (`acceptedAnswers`, `baremRule`/`subCriteria`).

Второй тест **sb25** (тот же офиц. формат) — заготовка на следующий цикл, вне скоупа.

- `npm run seed` (`scripts/seed-packs.ts`) + `src/data/chunks/*` — пайплайн чанков → паков.

## Компоненты

### 1. Модель данных (новое, статический модуль — без миграции IndexedDB)

Файл `src/data/exams/romanian-pr26.ts` (read-only контент, как `src/data/subjects/*`):

```ts
ExamPaper = {
  id, subjectId: 'romanian', year, title,
  timeLimitMin, totalPoints,
  items: ExamItem[],
}

ExamItem = {
  id, order,
  type: 'short' | 'open' | 'correctness',  // MCQ в этом формате нет
  prompt,                 // текст задания
  maxPoints,
  baremRule,              // текст правила начисления из колонки «Specificări» офиц. барема
  acceptedAnswers?,       // из «Răspuns corect/posibil»: эталон/принятые варианты (для short и как ориентир LLM)
  subCriteria?,           // структурный под-барем, если задан (напр. п.9, п.10)
}

SubCriterion = { id, title (RU/RO), maxPoints, rule }
```

`sourceText` (текст для чтения, общий для заданий) хранится на уровне `ExamPaper`, а не
повторяется в каждом `ExamItem`.

Типы — в `src/types/` (рядом с `subject.ts`). Регистрация выбранного теста — простой
экспорт + индекс (по аналогии с `src/data/chunks/index.ts`). Текст теста дополнительно
заводим как `ChunkDraft[]` в `src/data/chunks/romanian.chunks.ts`, чтобы тьютор обосновывал
объяснения; пересобираем `npm run seed`.

### 2. Ingestion (разово, на этапе разработки, не в рантайме)

Из PDF выбранного теста + барема (PDF с извлекаемым текстом) вручную/с помощью ассистента
структурируем в модуль `romanian-pr26.ts`. Никакого OCR/парсера PDF в продукте.

### 3. Грейдер по барему (ядро)

Файл `src/learning/baremGrader.ts` (+ тест). Вход: `(item, studentAnswer, llmCtx?)`.
Выход:

```ts
BaremResult = {
  perCriterion: { id, awarded, max, comment }[],
  total, max,
  advice,                 // точечный совет на языке поддержки (ru)
  mode: 'deterministic' | 'llm' | 'self',   // как получен балл
}
```

**Важно (по реальному барему pr26):** MCQ нет; почти все задания — открытые с
структурированным под-баремом. Детерминированный путь узкий — это норма для данного формата.

- `short` (п.2 синонимы/антонимы, п.7 целевая форма) → сначала детерминированно:
  нормализованное сравнение `studentAnswer` с `acceptedAnswers` (обрезка пробелов, регистр,
  диакритика, пунктуация). При несовпадении — LLM-добор (барем разрешает «alte variante
  adecvate»). Без LLM работает как минимум по точным совпадениям.
- `open` (п.1, 3, 4, 5, 6, 8, 9, 10) → LLM: новый шаблон `gradeAgainstBarem` в
  `src/llm/promptTemplates/`, собирает промпт из `item.baremRule` + `subCriteria` +
  `acceptedAnswers` (как ориентир) + `studentAnswer`; ответ модели валидируется (баллы по
  критериям ≤ maxPoints) по образцу `src/llm/validation.ts`. При недоступности LLM/провале
  валидации → `mode: 'self'` (откат на самооценку).
- `correctness` (п.11, 0–7, сквозной по числу орфограф./пункт. ошибок) → особый случай:
  для пилота — LLM-оценка с пометкой низкой уверенности либо самооценка. Не блокирует итог.
- Чистая, юнит-тестируемая функция; LLM-вызов инъектируется (как `getTutorFeedback`).

### 4. UI пробника

Новый экран `src/screens/Exam.tsx` (+ маршрут). Поток:

1. Старт пробника по `ExamPaper`: таймер на `timeLimitMin` (переиспользуем pomodoro-логику).
2. Задания по `order`; ввод ответа на каждое (textarea / выбор для mcq).
3. «Сдать» → по каждому заданию: разбор по барему (`BaremResult`), итог по тесту,
   точечные советы, источники RAG (как в `Practice.tsx`).
4. Сохранение попытки (см. §5).

Переиспользуем компоненты фидбека/источников/таймера из `Practice.tsx`; новый экран,
а не переделка Practice, чтобы не ломать существующий поток.

### 5. Захват данных пилота

- Попытку экзамена сохраняем как событие(я) (расширяем `LearningEvent` или добавляем
  лёгкий `ExamAttempt`-record): ответы, баллы по барему, итог, время, `mode` оценки.
- Расширяем `exportService` + `ExportScreen`, чтобы выгрузка включала попытки.
- В конце пробника — мини-фидбек: 1–2 вопроса (понятно? полезно?), сохраняется в попытку.
- Канал сбора экспортов (почта/диск) — вне приложения, ручной.

## Вне скоупа (YAGNI на эти 5 дней)

Несколько тестов; транскрипты видеоуроков; OCR; бэкенд для сбора данных; адаптивная
последовательность внутри пробника; другие предметы. Видео и доп. тесты — следующий цикл.

## Провайдер LLM в пилоте (решить до запуска, не блокирует разработку)

Фича провайдер-нейтральна. Рекомендация по умолчанию — **облачный OpenAI-совместимый**
(общий ключ/эндпоинт): единственный, что «просто работает» на любом устройстве за 5 дней.
Альтернатива при наличии доступного по сети HTTPS-эндпоинта — **ваш сервер (OVMS/Ollama)**:
приватнее, но требует доступности/CORS. «Локально у каждого» — нереалистично за 5 дней.
Решение — на этапе 13.06 (прогон/деплой).

## Риски и смягчение

- **Качество LLM-оценки открытых заданий** → детерминированно-первый подход; консервативный
  промпт; показываем барем ученику для самопроверки; самооценка как фоллбэк; калибровка
  промпта по реальному барему (и по 1–2 прошлым ответам учеников, если есть).
- **Провайдер не решён** → провайдер-нейтральная сборка; пробник работает без LLM на
  закрытых заданиях.
- **Время** → грузим только ОДИН тест; если LLM-оценка буксует — релизим детерминированную
  часть + самооценку (деградация к стратегии ②).

## Критерии готовности (DoD первого спека)

- Один прошлогодний тест загружен как `ExamPaper` + RAG-чанки (`npm run seed` проходит).
- Закрытые задания оцениваются детерминированно (юнит-тесты на грейдер).
- Открытые задания оцениваются LLM по барему с валидацией и фоллбэком на самооценку.
- `Exam.tsx` проходит пробник end-to-end: таймер → ответы → разбор по барему → итог → сохранение.
- Попытка экспортируется в JSON; есть мини-фидбек в конце.
- `npm run typecheck` и `npm test` зелёные.
